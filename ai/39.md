# Project Quentin – Meta-Agent v3 (Research-Integrated Edition)

> 一个可自我迭代、可持续学习、可自编程的 **通用智能体操作系统骨架**。  
> 你只需要：
> - 接入任意 LLM（本地 / 云端均可）
> -（可选）挂上你自己的领域工具（Desktop / Legal / Trading / ……）
>  
> 就可以开始做：**自我学习、自演化、自改代码** 的实验。

---

## ✨ 核心目标

本仓库实现的是《Meta-Agent 工程落地蓝皮书 v3》的工程骨架：

1. **通用性**  
   - 不绑定任何具体领域：Desktop / Legal / Trading / Research ……都只是 Domain。  
   - 不绑定任何具体 LLM：只需要实现一个统一的 `call_llm` 接口即可。

2. **自进化能力**（在安全边界内）  
   - 持续记忆：三层 MemoryFabric（STS/MTS/LTS）+ 巩固 / 衰减机制。  
   - 自编程：Self-Programming Engine + Patch 流水线（生成 → 测试 → 评估）。  
   - 技能进化：从 Trace → Episode → Skill Mining → Skill Library。

3. **研究友好**  
   - 所有核心闭环（认知 / 免疫 / 睡眠 / 演化）都有明确的输入 / 输出 / 指标。  
   - 自带 Observability API：一键接入 Grafana 或前端仪表盘。  
   - Research Layer 提供 ExperimentOrchestrator / EvolutionStrategy / Budget / Policy 骨架，方便替换论文里的算法，做 A/B 测试。

🔌 如何接入你自己的 LLM
当前骨架对 LLM 是完全脱耦的，你只需要实现一个统一的调用接口，然后在以下几个位置挂进去：

ModelRouter：注册你的模型信息

from quentin.models.router import ModelRouter, ModelInfo

router = ModelRouter()
router.register_model(
    ModelInfo(
        name="gpt-4.1",
        kind="openai",
        cost_per_1k_tokens=0.03,
        latency_hint_ms=800,
        domains=["demo", "generic"],
        tags=["high_quality"],
    )
)
BaseRoleAgent.run：改为真实 LLM 调用

在 quentin/agents/roles.py 里，把占位实现：

content = f"[{self.name}] would call model '{model_name}' with prompt: ..."
替换为类似：

llm_output = await call_llm(
    model_name=model_name,
    messages=[{"role": "user", "content": inp.prompt}],
)
content = llm_output["content"]
Planner / Critic / SelfProgrammingEngine 等模块

Planner：用 LLM 来生成分步 Plan。

Critic：用 LLM 进行 Reflexion，生成更丰富的 lessons_learned。

SelfProgrammingEngine：用 LLM 生成 Patch diff + Test 代码。

整个系统对 LLM 只假设一件事：
“你能根据 prompt 返回一段文本/结构化结果”。
怎么调用（本地 ollama / OpenAI / DeepSeek / 自建推理）完全由你决定。

🧠 四个闭环（Loop）怎么协同工作？
认知循环（Cognitive Loop）

接任务 → 调用 Planner 生成 Plan → Executor 执行 → Critic 复盘 → 写 Trace + Memory。

所有步骤都有 TraceSpan 记录，进入 Trace Store。

免疫循环（Immune Loop）

监测错误率 / 成本 / 延迟等异常。

触发时：

降级部分功能（关闭自改代码 / 降低探索强度）。

记录 ImmuneCase，交给 Research Layer 分析。

睡眠循环（Sleep / Consolidation Loop）

周期性运行（可配置：daily / hourly / manual）。

执行：

从 TraceSpan 聚合 TraceEpisode。

SkillMiner 从 Episode 中抽取技能模式 → 写入 SkillLibrary。

MemoryFabric.consolidate_once：晋级 STS → MTS、标记需要衰减的记忆。

技能与代码进化循环（Skill & Code Evolution Loop）

输入：

高成功率的 Trace / Episode。

ImmuneLoop 标记表现差的模块。

Skill 部分：

SkillMiner 生成新的技能定义 + 测试用例。

Code 部分：

SelfProgrammingEngine 生成 Patch + 测试 + 评估。

通过 PolicyEngine / BudgetController / ExperimentOrchestrator 决定是否上线。

🧪 Research Layer：如何做算法实验？
你可以用两种方式来做研究：

1. 替换内部算法
直接在这些位置换掉默认实现：

MemoryFabric.consolidate_once → 替换为你的 Continual Learning 策略。

SkillMiner.mine_from_episodes → 替换为你的技能抽取算法。

SelfProgrammingEngine.generate_patch → 换成你的「代码生成 + 测试」pipeline。

MultiAgentCoordinator.run_multi_view → 做 multi-agent debate / voting。

2. 使用 ExperimentOrchestrator 做 A/B 测试
示例（伪代码）：

from quentin.research.experiment_schemas import ExperimentConfig, ExperimentVariant

cfg = ExperimentConfig(
    target_module="planner",
    metrics=["success_rate", "avg_cost"],
)

variants = [
    ExperimentVariant(variant_id="baseline", name="baseline", params={"strategy": "old"}),
    ExperimentVariant(variant_id="new", name="new_planner", params={"strategy": "new"}),
]

exp = await experiment_orchestrator.create_experiment(
    name="planner_baseline_vs_new",
    description="Compare old vs new planner strategy",
    config=cfg,
    variants=variants,
)

await experiment_orchestrator.run_experiment(exp.experiment_id)
rows = await experiment_orchestrator.compare_variants(exp.experiment_id, metric="success_rate")
print(rows)
你可以在 run_experiment 里接上真实数据集 / Replay Trace 做更严谨的评估。

🔐 安全与边界
蓝皮书 v3 强调：自演化必须在安全内核边界内进行。本仓库在工程骨架层面做了以下约束：

SafetyKernel 控制：

哪些模块可以被自编程引擎修改（只允许 /mutable/ 下标记为 auto_updatable 的模块）。

哪些域（domain）必须人工 Gate（例如 Trading / Legal）。

PolicyEngine 控制：

环境为 production 时，一律禁止自动应用 patch。

sandbox / staging 才允许自动 candidate patch 上线。

所有 Patch / Experiment / ImmuneCase / Skill 生成过程都有 Trace 记录，可审计、可回滚。
