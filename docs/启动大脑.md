现在大脑已经完全重置并准备就绪，你可以通过以下三种主要方式给它分配任务，让它开始“思考”并“行动”：


  1. 交互式立即执行（推荐：用于新功能的开发和探索）
  如果你想立刻看到大脑的思考过程和结果，直接使用 run-task 指令。这会触发完整的 认知循环 (Cognitive Loop)：

   python -m quentin.cli.qctl run-task --input-text "你的任务描述"


  示例：
  > python -m quentin.cli.qctl run-task --input-text "编写一个自动备份 data 目录到 data_backups 文件夹的 Python 脚本，并在
  quentin/mutable/utils/ 下创建一个工具类。"


   * 大脑会做什么：
       1. Planner 会议：几个专家模型开会商量怎么写备份逻辑。
       2. Executor 执行：调用 CoderTool 编写代码，调用 ShellTool 创建目录。
       3. Done 会议：模型们检查备份是否真的成功了。
       4. 记忆存入：把这次成功的备份经验存入 memory.db。

  ---

  2. 队列式后台执行（推荐：用于批量任务或耗时任务）
  如果你有很多任务，或者想让它在后台慢慢磨，可以使用任务队列。

   1. 放入任务：


       python -m quentin.cli.qctl task-enqueue --input-text "任务 1" --priority 10
       python -m quentin.cli.qctl task-enqueue --input-text "任务 2" --priority 5
   2. 启动“工人”消化队列：
       # 启动后台守护进程，持续处理队列里的任务
       python scripts/run_brain_daemon.py --from-queue

  ---


  3. 蓝图驱动的自演化（推荐：让大脑“自强不息”）
  这是 Project Quentin 的核心——自发性任务。


  只要你开启了 BrainDaemon，它会定期扫描 blueprint/spec_v3.json。
   * 如果发现某个功能点（Capability）还没写完，或者没有测试证据。
   * 它会自动生成一个任务并放进队列。
   * 它会自己研究代码，自己写补丁（Patch），自己跑测试。


   # 启动自演化守护进程
   python scripts/run_brain_daemon.py --blueprint-autopatch

  ---

  💡 现在的第一个建议任务：

  既然我们刚才在会议中通过了 “Git 分支沙盒方案”，我们可以让它把这个方案落地为代码。

  你可以尝试运行这个指令：


   python -m quentin.cli.qctl run-task --input-text "根据之前的专家会议决议，在 quentin/infra/git/ 目录下实现一个 SandboxGitManager
   类。它需要支持：1. 基于当前任务 ID 创建 feature/ 分支；2. 在该分支运行 pytest；3. 只有测试通过后才允许合并回 main。"


   按照以下步骤，你就可以启动这个任务并全程掌控大脑的“心路历程”：


  1. 启动命令 (Start)
  在终端输入以下命令。这会启动认知循环，模型们会开始开会商量如何包装 gemini-cli：


   LLM_STUB=0 python -m quentin.cli.qctl run-task --input-text "在 quentin/infra/tools/ai_cli.py 中实现 GeminiCLIWrapper。要求：1.研究并定义专门给 Gemini CLI 使用的高级 Prompt 模板（包含代码上下文注入逻辑）；2. 封装 shell 调用逻辑；3.实现输出解析器提取代码块。"

  ---


  2. 如何看它的运行 (Monitor)
   * 实时观察：终端会持续打印点点点 ....（这是我刚才为你写的心跳机制，防止超时）。
   * 看“专家发言”：如果你想看 AI 们在会议室里吵什么，可以另开一个窗口运行：
       tail -f data/traces.jsonl
      你会看到 `planner` 会议中每个专家的原始发言。

  ---


  3. 什么时候结束 (Finish)
  当终端输出以下内容时，代表任务结束：
   * `Is Done : True`：表示大脑认为任务已圆满完成。
   * `Confidence : 1.000`：表示模型对结果非常有信心。
   * `Final output`：会打印一小段总结，告诉你它写了哪些类，改了哪些文件。

  ---

  4. 哪里看成品和报告 (Artifacts & Report)

  成品（代码）：
  直接去代码目录看，你会发现新生成的文件：
  > `quentin/infra/tools/ai_cli.py`


  结构化报告 (Report)：
  任务结束后，运行以下命令生成一份精美的 Markdown 审计报告：


   # 1. 导出记忆
   python -m quentin.cli.qctl memory-export

   # 2. 查看报告
   # 最新的会议决议和执行结果会在这个文件里：
   ls data/memory_markdown/short_term.md

  Patch 评估报告：
  如果大脑在过程中产生并尝试应用了代码补丁，你可以去这里看详细的“安全与质量评估”：
  > `data/patchflow_reports/`
