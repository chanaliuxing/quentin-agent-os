# Meta AI 自编程模块深度研究（融合版 Blueprint）

> 核心目标：
> 在本地 LLM 为主、codex/gemini 等工具为辅的前提下，
> 让系统能**自动读蓝皮书 / 找 gap / 生成补丁 / 自测 / 自审 / 递交给治理层**，
> 并且**可回滚、可追溯、可控、不炸库**。

---

## 一、问题重述 & 硬约束

### 1. 自编程的本质

* 改的是「业务代码」
* 也要改「改代码的代码」（SelfProgrammingEngine 本身）
* 只能在**有限资源+本地模型**下做这件事

→ 必须同时满足：

1. **可验证**：任何改动都要证明“至少不比旧的更差”
2. **可回滚**：一旦出问题能瞬间退回稳定版本
3. **可追溯**：知道每一行代码是谁、因为什么被改
4. **可控**：能限制改动范围（只动 `mutable/`，不动 `kernel/`）
5. **本地优先**：默认用本地 LLM，外部 codex/gemini 是加速器而不是刚需
6. **结构清晰**：让未来人接手时能看懂每一步是谁做出什么决策

## 二、总架构：5 层 + 1 条编程流水线

我们采用 Comet 的 **L1~L5 五层架构**，但把「真正写代码」这一块统一收敛到一个 **ProgrammingTeam Pipeline** 里，由 `SelfProgrammingEngine` 调用。

### 2.1 分层结构（概念）

```text
┌─────────────────────────────────────────────┐
│ L5 Meta-Programming                        │
│ （优化整个自编程系统的策略和参数）         │
└────────────────────┬───────────────────────┘
                     │
┌────────────────────┴───────────────────────┐
│ L4 Strategy-Level Evolution                │
│ （优化 Prompt / Planner 策略 / 路由逻辑）│
└────────────────────┬───────────────────────┘
                     │
┌────────────────────┴───────────────────────┐
│ L3 Tool & Skill Evolution                  │
│ （Skill Mining + Skill Registry + 工具演化）│
└────────────────────┬───────────────────────┘
                     │
┌────────────────────┴───────────────────────┐
│ L2 Patch Generation & Verification         │
│ （核心：ProgrammingTeam 自编程流水线）    │
└────────────────────┬───────────────────────┘
                     │
┌────────────────────┴───────────────────────┐
│ L1 Sandbox & Rollback                      │
│ （Git/目录沙箱 + 版本血缘 + 回滚机制）    │
└─────────────────────────────────────────────┘
```

### 2.2 一条贯穿 L2 的「AI 编程流水线」

L2 的核心就是 **SelfProgrammingEngine + ProgrammingTeam（Architect/Programmer/Tester/Reviewer）**：

```text
BlueprintGap
   ↓
SelfProgrammingEngine
   ↓ 构造 ProgrammingTask
ProgrammingTeam.run(task):
   1. Architect   → DevPlan
   2. Programmer  → CodePatchSet（FileModifications）
   3. Tester      → TestPlan + TestReport
   4. Reviewer    → ReviewDecision
   ↓
PatchProposal（封装上面所有结果）
   ↓
PatchEvaluator / GovernanceCouncil / Sandbox Apply
```

> 你可以理解为：
> **L2 是“大型 CI Bot”，ProgrammingTeam 就是 Bot 里的四个角色。**
> L1~L5 决定它在什么环境、什么频率、用什么策略、如何进化自身。

## 三、核心数据结构 & 血缘体系

### 3.1 血缘层：VersionLineage + PatchProposal 扩展

沿用 Comet 的思想，但稍微简化，落在当前 Git/目录沙箱语义上：

`VersionLineageTree` 管理这些版本；真正的「代码内容」还是放在 Git 里（tag/branch + patch 存档），或者简单用 `snapshots/` 目录存一份。

### 3.2 编程任务 &结果：ProgrammingTask → ProgrammingResult

```python
@dataclass
class ProgrammingTask:
```

```python
    rationale: str                     # 改动理由（方便人/AI 审查）
```

```python
@dataclass
class CodePatchSet:

```

```python
@dataclass
class DevPlan:

    work_items: list[dict]         # 每个 work_item 描述改哪些文件、目标行为

```

```python
@dataclass

```

## 四、ProgrammingTeam：四角色流水线（本地优先）

### 4.1 Architect（架构师）

**目标**：从 gap + 代码 + 蓝皮书，生成高层次的 DevPlan。

* 输入：`ProgrammingTask`（含 gap 描述 + section 文本 + available_file_list）
* 输出：`DevPlan`

**具体策略：**

1. **先看目录结构，不一次性塞所有代码进上下文**

   * REPL/工具层先收集：

     * 文件树（只包含路径+大小）
     * 部分关键文件内容（蓝皮书里提到的模块）
   * Architect 第一轮输出：

     * 哪些文件需要看全文
   * 第二轮再按需加载选中的文件内容，生成最终 DevPlan

2. **强制 JSON 输出（配合 Grammar 或重试）**

   * 使用 `Pydantic + 重试` 或本地 LLM 的 JSON/GBNF 约束
   * 防止“多话、乱写注释”破坏 JSON

3. **DevPlan 内容重点：**

   * `work_items`：每个小任务对应一组文件和高层步骤
   * `test_plan`：至少说明应该新增/修改哪些测试文件

> Architect 只做「决定改什么、为什么这么改」，不直接写代码。

---

### 4.2 Programmer（程序员）

**目标**：根据 DevPlan，生成 `CodePatchSet`。

* 输入：`DevPlan + ProgrammingTask`
* 输出：`CodePatchSet`

**关键设计：FilePatcher + search_replace 模式**

本地 LLM 不擅长 diff 行号 → **不让它写 diff**。
改为让模型输出如下格式的块：

```text
<<<< FILE: meta_agent/memory/fabric.py
<<<< SEARCH
class MemoryFabric:
    def __init__(self):
        self._mem = {}
====
class MemoryFabric:
    def __init__(self, backend: Optional[StorageBackend] = None):
        self._backend = backend or InMemoryBackend()
        ...
>>>>
```

Programmer 这一层做两件事：

1. 把 `DevPlan.work_items` 展开成一个个「文件级任务」
2. 对每个文件：

   * 加载当前文件内容
   * 向 CodeTool（默认 LocalLLMTool）发送：

     * 任务说明
     * 部分文件内容（或全文，视大小）
   * 收到 search_replace 格式，交给 `FilePatcher` 去实际应用

`FilePatcher` 要负责：

* 多次匹配 `original_snippet`：

  * 0 次 → 报错，任务失败
  * 1 次 → 应用
  * > 1 次 → 标记“歧义”，丢给 Reviewer / 下轮处理
* 确保 patch **幂等**：

  * 再跑一次不会重复插入

**本地优先策略：**

* 默认用 `LocalLLMTool`（qwen/deepseek 本地模型）
* 若：

  * 同一文件连续 2~3 次语法检查失败
  * 或测试始终不过且错误集中在某几个函数
    → 允许 fallback 用 `CodexCliTool` 或 `GeminiCliTool` 对特定函数做重写/建议

---

### 4.3 Tester（测试工程师）

**目标**：生成/补全测试 + 执行测试 → `TestReport`。

* 输入：`DevPlan.test_plan + CodePatchSet`
* 输出：`TestPlan + TestReport`

**流程：**

1. **测试生成/补全**

   * 根据 `DevPlan.test_plan` + 受影响文件列表：

     * 让某个 CodeTool 生成/修改 `tests/...` 文件
       （同样用 search_replace/full-file）
   * 这一步也走 FilePatcher

2. **快速语法检查（低成本守门）**

   * 对所有修改后的 `.py` 文件做一次 `ast.parse`：

     * 如果挂了 → 直接判定当前 patch 本轮失败，
       错误信息反馈给 Programmer 作为下一轮提示

3. **运行测试命令**

   * v1 阶段可以只支持 `pytest`
   * 在当前「代码沙箱 Git 工作副本」里执行：

     ```bash
     pytest -q <受影响模块对应的测试子集>
     ```
   * 收集 exit_code + stdout/stderr

4. **TestReport**

   * `overall_status`：

     * 所有相关测试过 → passed
     * 有挂但部分过 → partial
     * 全挂或关键测试挂 → failed

> 这里先用「**进程级沙箱 + Git 工作副本**」，以后再接 Docker。

---

### 4.4 Reviewer（代码审查员）

**目标**：对 patch+测试结果给出结构化审查意见 → `ReviewDecision`。

* 输入：`DevPlan + CodePatchSet + TestReport`
* 输出：`ReviewDecision`

**方法：**

* 用本地 LLM（可以配合 council）做 static review：

  * 检查是否符合 DevPlan 意图
  * 是否引入明显 bug 风险
  * 风格是否符合基本规范
* 输出 JSON：

  * `status`: approve / request_changes / reject
  * `issues`: 每个问题包含类型 / 位置 / 建议

**简单策略：**

* 测试未全过 → 强制 `status != approve`
* Trading / Legal 高风险模块 → Reviewer 无法 approve，只能 `request_changes` 或标记为需要人工审查，由 GovernanceCouncil 卡住

## 五、工具层：CodeToolRegistry & Local-First 策略

### 5.1 抽象接口：CodeToolBase

```python
class CodeToolBase(ABC):
    name: str

    @abstractmethod
    def generate_modifications(self, request: CodeEditRequest) -> list[FileModification]:
        ...

    @abstractmethod
    def generate_tests(self, request: TestGenRequest) -> list[FileModification]:
        ...
```

`CodeToolRegistry` 管理：

* `LocalLLMTool`（主力）
* `CodexCliTool`
* `GeminiCliTool`
* 静态工具（未来）：`RuffLinterTool` / `PyrightTool` 等

### 5.2 LocalLLMTool（本地主力）

* 用你的 qwen/deepseek 模型，通过 HTTP / CLI 调用
* Prompt 模式专门为本地模型优化：

  * 文件内容适量裁剪
  * 强约束输出格式（SEARCH/====/>>>>）
* 适合 80% 的常规变更

### 5.3 外部 CLI 工具（Codex/Gemini）

* 封装为 `ExternalCLITool`，通过 `subprocess` 调 CLI
* 使用场景：

  * 本地模型多次生成语法错误
  * 某些复杂语言/框架（Rust/Go/TS）本地模型不熟
  * Reviewer 想要第二意见

> 核心原则：**SelfProgrammingEngine 不直接知道 codex/gemini**，只知道「有一个叫 `codex_cli` 的 CodeTool」，可以随时换实现。

## 六、多层验证 & 安全策略（结合 Comet 的 8 层，分阶段落地）

### 6.1 v1 必须落地的 3 层

先实现一个 **可用版本**：

1. **Layer 1：语法检查**

   * `ast.parse` / `mypy --ignore-missing-imports`（可选）
2. **Layer 2：单元/集成测试**

   * pytest，至少跑与变更模块相关的测试
3. **Layer 3：基础静态分析**

   * 可选：调用 ruff/pylint，对严重问题（undefined variable / import error）直接挡住

这三层通过 → 才允许 Reviewer 讨论 “要不要交给 PatchEvaluator”。

### 6.2 v2 可以逐步增加的层

* **模糊测试/Fuzz**：对某些纯函数/解析逻辑做随机输入测试
* **回归测试**：保证旧用例全部仍然通过
* **性能基准**：基础性能对比
* **领域风险评估**：

  * Trading：禁止/警告更改风控逻辑
  * Legal：标记为必须人工复核

这些基本沿用 Comet 的设计，只是在你的系统里可以用 JSON 化封装，给 PatchEvaluator / GovernanceCouncil 用。

## 七、本地 LLM 友好型增强点

结合 Gemini 的那段评审，这些是 **专门为本地模型做的补强**：

1. **避免 diff，统一用 search_replace 或 whole-file rewrite**
2. **严格 JSON 输出**

   * 使用 Pydantic + 重试，或者 LLM 的 JSON/GBNF 限制
3. **上下文裁剪 / 分轮加载**

   * Architect 先选文件，再按需加载文件内容
4. **自动语法自检**

   * Programmer 每次生成代码后先 `ast.parse` 一下
   * 失败就把具体 SyntaxError 反馈回模型重新写
5. **失败分类**

   * 测试失败类型分：

     * 语法级
     * 逻辑级
     * 环境级（依赖缺失）
   * 方便下一轮提示更精准

## 八、与蓝皮书、PatchFlow、Orchestrator 的关系

1. **BlueprintImprovementLoop**

   * 找到 gap → 构造 `ProgrammingTask` → 调 SelfProgrammingEngine

2. **SelfProgrammingEngine**

   * 内部用 `ProgrammingTeam` 跑 1~N 轮
   * 成功 → 生成 `PatchProposal`
   * 失败 → 记录失败结果给 ImmuneLoop / ResearchLayer 做经验学习

3. **PatchFlow / GovernanceCouncil**

   * 对 `PatchProposal` 做补充评测（A/B Test 等）
   * 决定是否在 **沙箱 Git 工作区** 应用
   * 合格 patch 再由 L1 的 VersionLineage/Rollback 标记为候选稳定版本

4. **Orchestrator**

   * 决定什么时候触发这套自编程流水线：

     * Sleep Loop 夜间
     * Metrics/ImmuneLoop 发现异常时
     * 手动触发

## 1. `schema.py`：统一语言（Task / Plan / Patch / Test / Review）

```python
# meta_agent/self_programming/schema.py
from dataclasses import dataclass
from typing import List, Optional, Literal, Dict, Any


# === 基础 patch 单元：给 FilePatcher 用 ===

@dataclass
class FileModification:
    """
    单文件修改（最终交给 FilePatcher 执行）。
    """
    file_path: str
    action: Literal["create", "modify", "delete"]
    original_snippet: Optional[str]  # modify 时用于定位
    new_content: str                 # 替换后的内容（或新文件全量）


@dataclass
class CodePatchSet:
    """
    一次自编程生成的一组文件修改。
    """
    task_id: str
    files: List[FileModification]
    summary: str


# === 编程任务 & 团队各角色的输入输出 ===

@dataclass
class ProgrammingTask:
    """
    自编程任务：通常由 BlueprintGap / Bug 抽象而来。
    """
    task_id: str
    origin: Literal["blueprint_gap", "bugfix", "refactor", "experiment"]
    description: str                 # 人 & AI 可读描述
    repo_root: str                   # 仓库根目录
    related_files: List[str]         # Architect 可见文件范围
    context_summary: str             # 蓝皮书 gap / 失败 trace 等
    constraints: Dict[str, Any]      # 安全/风格/领域约束
    acceptance_criteria: List[str]   # 验收标准（明文化）



@dataclass
class DevPlan:
    """
    Architect 输出的开发计划。
    """
    task_id: str
    task_summary: str
```

```python
# meta_agent/self_programming/infra/git_ops.py
import subprocess
import uuid
from pathlib import Path


class GitSafetyLayer:
    """
    使用 Git 分支作为 AI 沙盒：
    - 为每个 task 创建 ai-dev/<task> 分支
    - 成功时提交 commit
    - 失败时回到原分支并删除沙盒分支
    """

    def __init__(self, repo_path: str = "."):
        self.repo_path = str(Path(repo_path).resolve())
        self._base_branch = self._get_current_branch()

    def _run(self, *args: str) -> None:
        subprocess.check_call(list(args), cwd=self.repo_path)

    def _get_current_branch(self) -> str:
        out = subprocess.check_output(
            ["git", "rev-parse", "--abbrev-ref", "HEAD"],
            cwd=self.repo_path,
        )
        return out.decode().strip()

    def create_sandbox(self, task_id: str) -> str:
        branch_name = f"ai-dev/{task_id[:8]}-{uuid.uuid4().hex[:6]}"
        # 从当前分支拉一个分支
        self._run("git", "checkout", "-b", branch_name)
        return branch_name

    def commit_work(self, message: str) -> None:
        self._run("git", "add", ".")
        # allow empty commit for trace
        try:
            self._run("git", "commit", "-m", message)
        except subprocess.CalledProcessError:
            # 可能没有变化，忽略
            pass

    def cleanup_sandbox(self, sandbox_branch: str) -> None:
        # 回到最初的 base branch
        self._run("git", "checkout", self._base_branch)
        # 删除临时分支
        self._run("git", "branch", "-D", sandbox_branch)
```

### 2.2 `file_patcher.py`：带模糊匹配的 FilePatcher（重点）

这个就是我们刚讨论的「阿喀琉斯之踵」，我直接给你一个可用版本（支持：

* exact 匹配
* 忽略空白的 fuzzy 匹配（相似度阈值）
* 幂等检查
* 歧义时不乱改，只给报告

）

```python
# meta_agent/self_programming/infra/file_patcher.py
from __future__ import annotations
from dataclasses import dataclass
from typing import Optional, Literal, List, Tuple
from pathlib import Path
import re
from difflib import SequenceMatcher

from meta_agent.self_programming.schema import FileModification


MatchKind = Literal["exact", "normalized", "fuzzy",
                    "already_applied", "ambiguous", "not_found"]


@dataclass
class MatchResult:
    kind: MatchKind
    start_idx: Optional[int] = None
    end_idx: Optional[int] = None
    similarity: Optional[float] = None
    candidates: Optional[List[Tuple[int, int, float]]] = None  # (start, end, sim)


@dataclass
class BlockApplyReport:
    file_path: str
    match_kind: MatchKind
    similarity: Optional[float]
    message: str


def normalize_whitespace(s: str) -> str:
    """
    用于宽松匹配：忽略缩进差异、多空格差异。
    """
    s = s.replace("\r\n", "\n").replace("\r", "\n")
    lines = [line.strip() for line in s.split("\n")]
    lines = [re.sub(r"\s+", " ", line) for line in lines]
    return "\n".join(lines)


def _split_lines_with_offsets(text: str):
    """
    返回 (line_text, start_idx, end_idx) 列表，
    便于从行号映射回字符区间。
    """
    lines = []
    start = 0
    for line in text.splitlines(keepends=True):
        end = start + len(line)
        lines.append((line, start, end))
        start = end
    return lines


class FilePatcher:
    """
    负责把 FileModification 应用到实际文件。
    支持：
    - 精确字符串匹配
    - 忽略空白的模糊匹配（相似度阈值）
    - 幂等检查（避免重复 patch）
    """

    def __init__(self, similarity_threshold: float = 0.95):
        self.similarity_threshold = similarity_threshold

    # ==== 对外接口 ====

    def apply_modifications(
        self,
        mods: List[FileModification],
        repo_root: str = ".",
    ) -> List[BlockApplyReport]:
        """
        批量应用修改，返回每个修改的报告。
        """
        reports: List[BlockApplyReport] = []

        # 按 file_path 分组，可以避免重复读写
        mods_by_file: dict[str, List[FileModification]] = {}
        for m in mods:
            mods_by_file.setdefault(m.file_path, []).append(m)

        root = Path(repo_root)

        for rel_path, file_mods in mods_by_file.items():
            path = (root / rel_path).resolve()
            if not path.exists() and any(m.action == "modify" for m in file_mods):
                # 修改一个不存在的文件，先读为空内容（或报错）
                text = ""
            elif path.exists():
                text = path.read_text(encoding="utf-8")
            else:
                text = ""

            new_text, file_reports = self._apply_to_text(text, file_mods, rel_path)
            # 只要有成功改动就写回文件
            if new_text != text:
                path.parent.mkdir(parents=True, exist_ok=True)
                path.write_text(new_text, encoding="utf-8")

            reports.extend(file_reports)

        return reports

    # ==== 内部实现 ====

    def _apply_to_text(
        self,
        original_text: str,
        mods: List[FileModification],
        file_path: str,
    ) -> tuple[str, List[BlockApplyReport]]:
        text = original_text
        reports: List[BlockApplyReport] = []

        for mod in mods:
            if mod.action == "delete":
                # 简化：整个文件删除交给上层处理，这里不实现局部删除
                # 你可以后续扩展为：如果 original_snippet 存在，就替换成 ""
                reports.append(
                    BlockApplyReport(
                        file_path=file_path,
                        match_kind="not_found",
                        similarity=None,
                        message="delete not implemented at FilePatcher level",
                    )
                )
                continue

            if mod.action == "create" and (not mod.original_snippet):
                # 直接全量写内容（针对新文件）
                text = mod.new_content
                reports.append(
                    BlockApplyReport(
                        file_path=file_path,
                        match_kind="exact",
                        similarity=None,
                        message="created new file content",
                    )
                )
                continue

            # modify 或 create + original_snippet != None，走匹配逻辑
            text, report = self._apply_single_block(text, mod, file_path)
            reports.append(report)

        return text, reports

    def _apply_single_block(
        self,
        text: str,
        mod: FileModification,
        file_path: str,
    ) -> tuple[str, BlockApplyReport]:
        orig = mod.original_snippet or ""
        if not orig:
            # 没有 original_snippet，直接当追加/覆盖处理
            new_text = text + ("\n" if not text.endswith("\n") else "") + mod.new_content
            return new_text, BlockApplyReport(
                file_path=file_path,
                match_kind="exact",
                similarity=None,
                message="no original_snippet given, appended new_content",
            )

        # 1) exact match
        idx = text.find(orig)
        if idx != -1:
            end = idx + len(orig)
            if self._already_applied(text, idx, end, mod.new_content):
                return text, BlockApplyReport(
                    file_path=file_path,
                    match_kind="already_applied",
                    similarity=1.0,
                    message="block already applied (exact slot)",
                )
            new_text = text[:idx] + mod.new_content + text[end:]
            return new_text, BlockApplyReport(
                file_path=file_path,
                match_kind="exact",
                similarity=1.0,
                message="applied with exact match",
            )

        # 2/3) normalized + fuzzy match
        match_res = self._fuzzy_match(text, orig)

        if match_res.kind in ("fuzzy", "normalized"):
            assert match_res.start_idx is not None and match_res.end_idx is not None
            idx, end = match_res.start_idx, match_res.end_idx
            if self._already_applied(text, idx, end, mod.new_content):
                return text, BlockApplyReport(
                    file_path=file_path,
                    match_kind="already_applied",
                    similarity=match_res.similarity,
                    message=f"block already applied (fuzzy slot, sim={match_res.similarity:.3f})",
                )
            new_text = text[:idx] + mod.new_content + text[end:]
            return new_text, BlockApplyReport(
                file_path=file_path,
                match_kind=match_res.kind,
                similarity=match_res.similarity,
                message=f"applied with {match_res.kind} match, sim={match_res.similarity:.3f}",
            )

        if match_res.kind == "ambiguous":
            return text, BlockApplyReport(
                file_path=file_path,
                match_kind="ambiguous",
                similarity=match_res.similarity,
                message=f"ambiguous fuzzy matches (n={len(match_res.candidates or [])}), no change applied",
            )

        return text, BlockApplyReport(
            file_path=file_path,
            match_kind="not_found",
            similarity=None,
            message="no suitable match found, block skipped",
        )

    def _fuzzy_match(self, text: str, original_snippet: str) -> MatchResult:
        """
        忽略空白的行级滑动窗口 + 相似度匹配。
        """
        orig_norm = normalize_whitespace(original_snippet)
        orig_lines = original_snippet.splitlines()
        n = max(1, len(orig_lines))

        lines_with_offsets = _split_lines_with_offsets(text)
        total_lines = len(lines_with_offsets)

        candidates: List[Tuple[int, int, float]] = []
        best_sim = 0.0

        for i in range(0, max(1, total_lines - n + 1)):
            window_lines = lines_with_offsets[i : i + n]
            window_text = "".join(l[0] for l in window_lines)
            window_norm = normalize_whitespace(window_text)
            sim = SequenceMatcher(None, orig_norm, window_norm).ratio()
            if sim >= self.similarity_threshold:
                start_idx = window_lines[0][1]
                end_idx = window_lines[-1][2]
                candidates.append((start_idx, end_idx, sim))
                if sim > best_sim:
                    best_sim = sim

        if not candidates:
            return MatchResult(kind="not_found")

        if len(candidates) == 1:
            s, e, sim = candidates[0]
            return MatchResult(
                kind="fuzzy", start_idx=s, end_idx=e, similarity=sim
            )

        # 多个候选：暂时标 ambiguous，由上层决定要不要自动选最高
        candidates.sort(key=lambda x: x[2], reverse=True)
        s, e, sim = candidates[0]
        return MatchResult(
            kind="ambiguous",
            start_idx=s,
            end_idx=e,
            similarity=sim,
            candidates=candidates,
        )

    def _already_applied(self, text: str, start: int, end: int, new_content: str) -> bool:
        """
        判断指定区间的内容是否已经非常接近 new_content（避免重复 patch）。
        """
        current_segment = text[start:end]
        if current_segment == new_content:
            return True
        old_norm = normalize_whitespace(current_segment)
        new_norm = normalize_whitespace(new_content)
        sim = SequenceMatcher(None, old_norm, new_norm).ratio()
        return sim > 0.99
```

```python
from typing import List
from pathlib import Path

from meta_agent.self_programming.schema import ProgrammingTask, DevPlan, CodePatchSet, FileModification
from meta_agent.self_programming.tools.base import CodeToolRegistry

            abs_path = (self.repo_root / file_path).resolve()

                task=task,
                file_path=file_path,
                file_content=content,
                instructions=instructions,
            )

            task_id=task.task_id,
            files=mods,
```

```python
            return ReviewDecision(
                task_id=task.task_id,
                status="reject",
                severity="high",
                issues=[{"type": "test_failed", "description": "pytest failed"}],
                summary="Tests failed, patch rejected",
                follow_up_actions=["fix failing tests or patch"],
            )

        return ReviewDecision(
            task_id=task.task_id,
            status="approve",
            severity="low",
            issues=[],
            summary="Tests passed, patch approved (rule-based v0)",
            follow_up_actions=[],
        )
```

## 5. `engine.py`：SelfProgrammingEngine 总控（Step 3）

```python
# meta_agent/self_programming/engine.py
from __future__ import annotations
from typing import Dict, Any

from meta_agent.self_programming.schema import (
    ProgrammingTask,
    ProgrammingResult,
)
from meta_agent.self_programming.infra.git_ops import GitSafetyLayer
from meta_agent.self_programming.infra.file_patcher import FilePatcher
from meta_agent.self_programming.tools.base import CodeToolRegistry
from meta_agent.self_programming.tools.local_llm import LocalLLMTool
from meta_agent.self_programming.agents.architect import ArchitectAgent
from meta_agent.self_programming.agents.programmer import ProgrammerAgent
from meta_agent.self_programming.agents.tester import TesterAgent
from meta_agent.self_programming.agents.reviewer import ReviewerAgent


class SelfProgrammingEngine:
    """
    一次完整的自编程循环：
    - GitSafetyLayer 建沙盒分支
    - Architect → DevPlan
    - Programmer + CodeTool → CodePatchSet
    - FilePatcher 应用改动
    - Tester 跑测试 → TestReport
    - Reviewer 决定是否接受 → ReviewDecision
    - 成功：commit 并保留分支；失败：回到 base 并删除沙盒
    """

    def __init__(self, repo_root: str = "."):
        self.repo_root = repo_root
        self.git = GitSafetyLayer(repo_root)
        self.patcher = FilePatcher()

        # 工具注册
        self.tools = CodeToolRegistry()
        self.tools.register(LocalLLMTool())

        # 团队
        self.architect = ArchitectAgent()
        self.programmer = ProgrammerAgent(repo_root=repo_root, tools=self.tools)
        self.tester = TesterAgent(repo_root=repo_root)
        self.reviewer = ReviewerAgent()

    def run_task(self, task: ProgrammingTask) -> ProgrammingResult | None:
        """
        外部调用入口：给一个 ProgrammingTask，跑一轮自编程。
        返回 ProgrammingResult（成功/失败都要落日志）。
        如果中途发生 fatal error，会返回 None。
        """
        sandbox_branch = self.git.create_sandbox(task.task_id)
        try:
            # 1) Architect
            dev_plan = self.architect.analyze(task)

            # 2) Programmer
            patch_set = self.programmer.implement(task, dev_plan)

            # 3) FilePatcher 应用到沙盒
            patch_reports = self.patcher.apply_modifications(
                patch_set.files, repo_root=self.repo_root
            )
            # 简单规则：如果有 not_found / ambiguous 太多，可以认为失败
            if any(r.match_kind in ("not_found", "ambiguous") for r in patch_reports):
                # 这里可以进一步打进 Trace，暂时简单处理
                raise RuntimeError("too many patch application issues")

            # 4) Tester
            test_plan = self.tester.build_test_plan(task, dev_plan)
            test_report = self.tester.run_tests(test_plan)

            # 5) Reviewer
            review = self.reviewer.review(task, patch_set, test_report)

            if review.status == "approve":
                self.git.commit_work(f"AI self-programming: {task.task_id}")
            else:
                # 审查没通过，认为本轮失败，回滚
                self.git.cleanup_sandbox(sandbox_branch)
                return ProgrammingResult(
                    task=task,
                    dev_plan=dev_plan,
                    patch_set=patch_set,
                    test_plan=test_plan,
                    test_report=test_report,
                    review=review,
                    tools_used=[t for t in self.tools.list_tools()],
                )

            # 审批成功，保留分支（你可以改成 merge 回 main，再删分支）
            return ProgrammingResult(
                task=task,
                dev_plan=dev_plan,
                patch_set=patch_set,
                test_plan=test_plan,
                test_report=test_report,
                review=review,
                tools_used=[t for t in self.tools.list_tools()],
            )

        except Exception as e:
            # fatal error：直接回退到 base 分支并删除沙盒
            print(f"[SelfProgrammingEngine] Fatal error: {e}")
            try:
                self.git.cleanup_sandbox(sandbox_branch)
            except Exception:
                pass
            return None
```
